§1  双爆最优配比 —— 解析解、数值验证与社区经验的适用边界
==============================================================================

【建模】
  暴击期望乘区  E(CR, CD) = 1 + CR·(CD - 1)
  记 D = CD - 1 为"超出非暴击的净暴伤"，则 E = 1 + CR·D。

  一条副词条的平均贡献：暴击率 +0.0840，暴击伤害 +0.1680。
  比值 2.0000 —— 一条暴伤词条恰好等于两条暴击率词条的数值量。
  据此定义词条预算 B（以"暴击率当量"计），把 B 拆成给暴击率的 x 与给暴伤的 B-x：
      CR = CR0 + x
      D  = D0 + 2(B - x)

【解析求解】
  E(x) = 1 + (CR0 + x)·(D0 + 2B - 2x)
  dE/dx = (D0 + 2B - 2x) - 2(CR0 + x) = 0
      ==>  D0 + 2B - 2x = 2·(CR0 + x)
      ==>  D* = 2·CR*
  二阶导 d²E/dx² = -4 < 0，为极大值。

  ★ 结论一（内点最优条件）：当  CD - 1 = 2 × CR  时暴击期望乘区取极大。
    这就是社区口口相传的"双爆 1:2"——本推导给出了它的数学出处，
    而非经验法则：它成立的前提是"一条暴伤词条 = 两条暴击率词条"这一档位设计。

【★ 结论二：社区经验的适用边界——角点在可达面板之外（v1.1 修订）】
------------------------------------------------------------------------------

  上面的解是"内点解"，它默认 CR 可以自由取值。但游戏内暴击率封顶 100%，
  一旦最优解要求的 CR* > 100%，问题就退化成角点解——此时正确策略是
  "把所有词条给暴伤"，而"1:2"反而是错的。

  求临界预算 B_c：令 CR* = 100%
      CR0 + ((CD0-1) + 2B - 2·CR0)/4 = 1

      ==> B_c = 1.7000 暴击率当量 = 20.2 条副词条当量

  也就是说：当角色从武器 / 共鸣链 / 声骸主词条 / 队友增益处已经拿到
  约 20 条词条当量以上的双爆资源时，才会退化到角点解。
  但副词条上限 5 暴击 + 5 暴伤 = 15 条当量，加武器 / 共鸣链约 +40% 暴击率
  （≈ 4.8 条当量）合计约 19.8 条，仍低于该临界值——角点在游戏内基本不可达。

  所以"1:2"在全部可达面板内都成立。外部暴击率来源改变的不是最优条件，
  而是达成同一面板所需的副词条分配（无外部来源时给暴击率 5 条，+40% 时
  降到 3 条）。口诀锚在最终面板，玩家算的是条数——两者在不同层面。

§2  词条档位比 2:1 与 CV 评分公式 —— 从数值设计反推玩家体验设计
==============================================================================

【观察】副词条档位区间：
    暴击率   0.063 ~ 0.105   （中值 0.0840）
    暴击伤害 0.126 ~ 0.210   （中值 0.1680）

  逐档核对上下界之比：
    下界比 2.0000      上界比 2.0000      中值比 2.0000

  三个比值全部精确等于 2.0000。这不可能是巧合——是设计上钉死的约束。
  但它证明的东西比 v1.0 以为的要少：

【★ 结论三（v1.1 修订）：真正的设计选择不是"2"，而是"把档位比钉成精确常数"】

  代数事实：对任意固定档位比 r，把预算 B 拆成 CR = CR0+x、D = D0+r(B-x)，
  最优条件都是 D* = r·CR*，且评分 r·CR + CD 在固定预算下是分配不变量
  （r·c·u + r·c·v = r·c·N，与分配无关）——**线性可加评分是"固定比"的
  代数产物，不专属于 2:1**。下面用 r = 1.5 / 2 / 3 数值验证。

  而 2:1 这个具体取值与原神一致（暴击率 2.7/3.1/3.5/3.9，
  暴伤 5.4/6.2/7.0/7.8，逐档精确 2:1）——按正文 §4.5 的判准，
  它是行业沿用解，不是库洛的独创设计。
  （v1.0 曾断言"2:1 是为 CV 可加性服务"并给出先后叙事——评审指出
  这是循环论证：任意固定比都有同样性质，先后无法证伪。）

  鸣潮的真实选择在下一层：移除强化随机。原神强化随机分配到 4 条中的
  任意一条，CV 无法在单条词条层面稳定预判；鸣潮把随机性收敛在"出不出
  这条词条"，副作用是单个声骸的价值可以在获得的瞬间被判定——
  这直接支撑了它"刷取快、判定快、弃置快"的养成节奏。

------------------------------------------------------------------------------
【验证 A】任意固定档位比 r 下，最优条件均为 D* = r·CR*，评分 r·CR+CD 恒定

  r=1.5: 最优点 D/CR = 1.494（理论 1.5），评分取值数 = 1（恒定 ⇒ 1）
  r=2.0: 最优点 D/CR = 1.993（理论 2.0），评分取值数 = 1（恒定 ⇒ 1）
  r=3.0: 最优点 D/CR = 2.994（理论 3.0），评分取值数 = 1（恒定 ⇒ 1）
------------------------------------------------------------------------------

§3  抗性分段函数 —— 连续性验证与系数 k=5 的唯一性反解
==============================================================================

【公开规则】
    R < 0      :  mult = 1 - R/2
    0 ≤ R < 0.8:  mult = 1 - R
    R ≥ 0.8    :  mult = 1 / (1 + 5R)

------------------------------------------------------------------------------
【连续性验证】（分段函数最容易出设计事故的地方）
------------------------------------------------------------------------------
  R = 0.0 :  左极限 1.000000   右极限 1.000000   取值 1.000000   连续 ✓
  R = 0.8 :  左极限 0.200000   右极限 0.200000   取值 0.200000   连续 ✓

【★ 结论四：系数 5 不是拍脑袋选的，它被连续性条件唯一确定】

  设高抗段形如 1/(1+kR)，要求它在 R=0.8 处与中段 1-R 无缝衔接：
      1 / (1 + 0.8k) = 1 - 0.8 = 0.2
      ==> 1 + 0.8k = 5
      ==> k = 5
  k 无自由度。这说明设计流程是"先定拐点 0.8 与中段线性式，再解出高抗段
  系数"，而不是三段各自调参——一个可以从公开数字反推出来的实现细节。

------------------------------------------------------------------------------
【一阶导（减抗的边际收益）】
------------------------------------------------------------------------------
  中段  d(1-R)/dR        = -1
  高抗段 d[1/(1+5R)]/dR    = -5/(1+5R)²，在 R=0.8 处 = -5/25 = -0.2
  负抗段 d(1-R/2)/dR       = -0.5

  函数连续但一阶导不连续。三段斜率 -0.5 / -1 / -0.2 对应三种设计意图：

    · 负抗段斜率减半：减抗堆到负数后收益打对折 —— 对"减抗流"配队的软性
      收益衰减，防止减抗成为无脑最优解。R 从 0 打到 -100% 只拿到
      ×1.50 而非 ×2.00。

    · 中段线性：玩家直觉区。"敌人 20% 抗性 = 少 20% 伤害"，所见即所得。

    · 高抗段双曲：伤害倍率恒为正，敌人永不免疫。R=200% 时仍有
      ×0.0909，R=1000% 时 ×0.0196。
      这是一道数值安全阀 —— 设计师可以放心给后期敌人堆高抗做检查点，
      不必担心某个抗性数字把玩家伤害归零、造成不可通关的死局。

§4  等级压制曲线 —— 一个否定性发现：防御区不是差异化设计点
==============================================================================

【公开公式】
    鸣潮 防御乘区 = (800 + 8·L_攻) / (800 + 8·L_攻 + DEF_目标·(1 - 无视防御))
    社区通行简化式（怪物防御按等级拟合后）：
         鸣潮 ≈ (100 + L_角色) / (199 + L_怪物 + L_角色)
         原神 =  (100 + L_角色) / (200 + L_怪物 + L_角色)

【★ 首先要说的是一个我自己推翻掉的假设】

  本拆解案初稿曾写下"鸣潮的等级压制显著温和于原神，因此把门槛从练度
  转移到了操作"。落笔前把两个公式并排代入，结论被自己证伪：
  两式分母仅差 1，是同一个函数。下面用数值逐点验证。

【★ 结论五（否定性结论）：防御乘区是被两家共享的行业标准解，
    等级压制强度实质相同 —— 这里没有产品差异化】

  · 同级（90 vs 90）：防御乘区 0.5013
  · 越级 10 级（90 vs 100）：0.4884，损失 2.57%
  · 碾压 10 级（90 vs 80）：0.5149，增益 2.71%
  · 原神在同样条件下的三个数字：0.5000 /
    0.4872 / 0.5135

  两者每级衰减都在 0.26% 量级，等级差 ±10 只带来约 ±2.5% 的伤害摆动。
  也就是说，"练度不够打不动"这一常见体验**不来自防御乘区**。

  这个否定性结论有两点用处：

  (1) 纠正一个流行的归因错误。玩家侧常把越级挑战的吃力归咎于"等级压制"，
      但防御区在两款产品里都温和到可以忽略。真正的练度门槛来自另外两处：
      角色等级带来的**攻击力面板成长**（进入基数区，是乘区里权重最大的
      一项），以及敌人**血量随等级的成长**（不在伤害公式内，但直接决定
      击杀所需回合数）。策划做数值时若混淆这三者，会把调参调在错误的
      旋钮上。

  (2) 反向界定了鸣潮真正的差异化位置。既然防御区被抄作业式地共享，
      那么它与同赛道产品的区别必然落在别处 —— 从本拆解案的其余章节看，
      落在**抗性段函数的钳制方式**（§3）、**随机性在养成链上的位置**
      （§5，筛选制 vs 强化制）、以及**协奏值把切人资源化**（正文 §3）。
      这三处才是值得展开的设计选择。

  方法论备注：拆解案里敢于写"这里没有特殊设计"，比给每个数字都硬编一个
  设计意图更接近真实的策划工作。数值系统里存在大量行业沿用解，识别出
  哪些是沿用、哪些是选择，本身就是拆解能力的一部分。

§5  声骸词条命中率 —— 超几何模型与期望毕业成本
==============================================================================

【建模假设（须以实测校验，见拆解案 §7 待实测清单）】
  · 副词条池按社区通行的 13 种建模：暴击率, 暴击伤害, 攻击力%, 攻击力(数值), 生命值%, 生命值(数值), 防御力%, 防御力(数值), 共鸣效率, 普攻伤害加成, 重击伤害加成, 共鸣技能伤害加成, 共鸣解放伤害加成
  · 5 条副词条互不重复 —— 因此是**不放回抽样**，服从超几何分布，
    而非许多攻略文默认的二项分布（后者会系统性高估双爆同出概率）。
  · 本节先按等概率建模求出上界，实测概率非均匀时结论只会更差。

【4C 完美毕业件的期望成本】
------------------------------------------------------------------------------
  一件"可用的 4C 主 C 声骸"需要同时满足：
    (1) 套装正确
    (2) 主词条为暴击率或暴伤（4C 随机主词条 6 选 1 中的 2 种）
    (3) 副词条含双爆（且主词条已占其一时，池中相应减少）

  P(套装) = 0.2000   （无定向假设的保守上界，敏感度见下表）
  P(主词条命中双爆) = 0.3333
  P(副词条含另一个双爆 | 主词条已占一个) = 0.4167

  P(全部命中) = 0.02778   ==>  期望 36.0 件 4C 声骸

  再叠加"档位要落在高档"这一层：若要求两条双爆均落在 8 档中的高 3 档，
  概率再乘 (3/8)² = 0.1406
      ==> 期望 256 件。

  【P(套装) 敏感度】游戏支持定向刷怪（怪物图鉴即掉落表），1/5 是
  无定向保守上界 [实测校验项：定向刷取的套装命中率]：
    P(套装)=0.200    无定向（上界）  期望   36.0 件   加档位要求   256.0 件
    P(套装)=0.333        弱定向  期望   21.6 件   加档位要求   153.6 件
    P(套装)=0.500        强定向  期望   14.4 件   加档位要求   102.4 件


【★ 结论六：养成系统的随机性预算被刻意压在"筛选"而非"强化"】

  声骸不能重洗、不能定向强化，副词条按调谐档位逐条揭示且揭示后不可重投。
  与"强化次数随机分配"相比，它的体验优势是**沉没成本被切成五段可退出的
  小额**：每揭示一条就是一个止损点，不会像强化制那样"已经投入了资源，
  只好继续赌"——代价是每档揭示消耗调谐器与声骸经验（体力门控）。

  代价是刷取次数的方差极大（上表的期望值背后是长尾分布），所以库洛必须
  用另外两个设计来兜底：
    · 声骸掉落与大世界怪物强绑定、刷取无体力硬门槛（把"次数"变便宜）
    · 数据坞的"吸收即可合成"（把保底做在合成侧而非强化侧）
  ==> 三者是一套的：不可重洗 → 必须高频刷 → 必须去掉刷取摩擦。
      单看任何一条都会误判为"设计缺陷"，合起来看才是完整的成本结构。


==============================================================================
§6  边际收益敏感度 —— 给定当前面板，下一条词条应该要什么
==============================================================================

【方法】固定其余乘区，比较单条词条带来的总伤害相对增量：
    · 暴击率 +8.40%      （档位中值）
    · 暴击伤害 +16.80%   （档位中值）
    · 攻击力 +8.60%      （按副词条攻击力% 档位中值估）
    · 属性伤害加成 +8.60%（与攻击力同量级，但落在增伤区）

  注意攻击力落在**基数区**、伤害加成落在**增伤区**、双爆落在**暴击区**，
  三者互为乘算 —— 因此边际收益取决于各自区内已堆叠的存量（收益递减）。

------------------------------------------------------------------------------
          场景     CR     CD     攻击区     增伤区      ΔCR      ΔCD      Δ攻击      Δ增伤         最优
------------------------------------------------------------------------------
        裸装新号   0.05   1.50    1.00    0.00    4.10%    0.82%    8.60%    8.60%        攻击力
         成长期   0.35   1.80    1.60    0.30    5.25%    4.59%    5.38%    6.62%         增伤
         成型队   0.65   2.20    2.20    0.60    5.66%    6.13%    3.91%    5.37%         暴伤
        满配毕业   0.80   2.60    2.60    0.90    5.89%    5.89%    3.31%    4.53%         暴伤
       暴击率溢出   0.95   2.40    2.40    0.80    3.00%    6.85%    3.58%    4.78%         暴伤

【★ 结论七：词条优先级不是一张静态表，而是面板的函数】

  多数攻略给出的"暴击率 > 暴击伤害 > 攻击% ≈ 增伤"是一个**平均意义上的
  近似**，它只在成长期区间成立：
    · 裸装期，暴击率的边际收益最高（基数 5% 时每一点都在撬动整个乘区）
    · 成型后，最优项随双爆存量迁移，且一旦暴击率接近封顶，
      它的边际收益断崖式归零（见"暴击率溢出"行）
    · 攻击力与增伤的边际收益只取决于**各自区内的存量**，与双爆无关 ——
      因此"堆到某个区特别高"永远是次优解，乘区结构天然奖励均衡

  ==> 作为策划的读法：这套乘区设计把"配装"变成了一个**每个人答案都不同
      的局部优化问题**，而不是一张可以抄的标准答案表。攻略的存在价值被
      从"给答案"改成了"给方法"，社区讨论的生命周期因此被拉长。
      这是数值结构对社区生态的隐性设计。
