Design Decisions
四个真实的设计取舍
全部来自开发过程中的真实迭代——问题由实机走查发现，结果经数据验证。
问题

终局 Boss 实测 4~5 回合即被击杀，"最终决战"没有决战感。

决策

不凭感觉加血——按玩家觉醒后的期望伤害逐回合检算，重设 HP 与攻击：良好作答者残血通关，低级失误者战败重试。

结果

战斗时长控制在 11~16 回合、玩家血线被压至 22~46%——险胜成为终局的默认体验。

问题

500 道 AI 生成题逐题核对全部正确，但玩家背"选项位"就能通关。

决策

对题库做聚合分布审计——发现 92–96% 的正确答案聚集在同一选项位（LLM 生成偏置），在显示层洗牌修复，不动数据源。

结果

偏置清零；沉淀出"逐项正确 ≠ 整体无病"的 AIGC 内容质检方法。

问题

精心设计的五元素克制环几乎没被使用——玩家整场只敢用一个技能。

决策

定位到问题不在克制环而在资源：专注每回合净流失，切技能等于浪费。上调回复与初始值，让"换元素"从奢侈变成常规选项。

结果

克制环真正进入每回合决策——资源经济决定一个系统是否被使用。

问题

"答题 = 攻击"的核心规则，新手第一场战斗看不懂。

决策

不加弹窗说明书——把教学拆进首战三拍（选元素 → 对 / 快 / 错反馈 → 克制提示），在真实战斗中逐步揭示规则。

结果

教学融入玩法本身、零打断——与《原神》新手关拆解案的结论互为印证。

UI 系统架构（UX）

从零搭建：9 个全屏页面 + 7 个 HUD 子模块 + 2 套覆盖系统。严格遵循 ECS 数据流——状态只存在 registry ctx 资源里，UI 渲染函数是纯消费者，禁止系统间直呼。

道具 / 装备系统

MGS 风格——网络安全主题道具（木马 / DDOS / 哈希混淆 / 防火墙诱导等）、快捷切换、径向四扇区道具轮盘（鼠标角度检测 + 冷却可视化）、数据驱动（.itemspawns）的地图内生成与拾取。

战役积分与评级（数值）

扣减制计分：开局 1000 分，逐秒 −1 / 击杀 −10 / 用道具 −5 / 触发倒计时 −200，F 至 SSS 八档评级并实时提示降档；分数跨三关累积，终关 >500 才算通关。用记分规则把"潜行"而非"清场"变成唯一最优解。

对话系统（为手柄设计）

方向键组合序列（↑↓←→）+ 前缀匹配的分支对话，配倒计时与可视化输入槽、发言者标记——玩法上正好对应"黑客敲指令麻痹管理员"。

HUD 七模块

生命/护甲、小地图（NavMesh 世界坐标 → 屏幕空间投影）、装备栏、罗盘、动作通知（Toast 六条队列）、交互提示（3D → 2D 投影）、聊天叠层——各读各的 ctx 资源，独立渲染。

跨平台与视觉特效

参与 PS5 移植与 DualSense 手柄适配；CRT 扫线 / 暗角 / 赛博朋克死亡动画。主题呼应我的网络攻防产品背景——把安全攻防知识转化成了一套玩法。

Design Decisions
四个真实的设计取舍
设计的价值不在做了什么，而在为什么这么做、换来了什么。
问题

默认深色 UI 主题千篇一律，和游戏氛围也不搭。

决策

反着做——用暖奶油底（#F5EEE8）+ 橙色强调（#FC6F29）。潜行游戏里罕见，但正因罕见才建立识别度。

结果

这套配色成了游戏的视觉签名，全队后续界面沿用。

问题

功能一多，单体 HUD 代码迅速变得没法维护，队友互相踩脚。

决策

把 HUD 拆成 7 个独立子模块，每个只读自己专属的 ECS ctx 资源，互不通信。

结果

改小地图的人不可能碰坏生命条——并行开发成为可能，这是 7 人团队按期交付的前提。

问题

鼠标点选式对话，搬到 PS5 手柄上体验很差。

决策

不做妥协式适配，而是重设计交互：方向键组合序列 + 前缀匹配。

结果

PC 鼠标 / 键盘与 DualSense 输入被统一；更意外的是，敲组合键本身成了玩法乐趣的一部分。

问题

30 多个 UI 文件里颜色和间距各写各的，视觉开始飘。

决策

抽出集中式 UITheme.h 作为唯一事实来源——色板、布局常量、样式参数全在里面。

结果

47 个文件视觉一致；换整站配色只需改一个文件。

泄题的威胁模型错了

剥离答案字段挡不住泄题——解析文本本身就含答案（实测 500 题 66.8% 命中）。护栏必须建在输出层，而不是数据层。

选模型漏了第四条标准

只比了价格 / 工具调用 / 上下文，没查默认推理行为——默认开思考导致首次调用 100% 空回复，且思考模式下 temperature 静默失效。

假阳性比漏报更危险

子串匹配分不清"使用"与"提及"，三次误报同一根因——误报会诱导你去修改本来正确的行为。

Why Me

策划，是玩家体验的产品经理

我不是科班直线进游戏行业的：信息管理本科、经济金融第二学位，先在一家 AI 攻防安全公司做了 2.75 年产品经理，才来纽卡读游戏工程。这条路绕，但绕出来的东西刚好是策划要用的。

工具换了，思维方式是同一套：先搞懂用户要什么，为这个需求做设计，拿数据迭代，然后按期把东西交出来。在 7 人团队的潜行游戏里，这段经验最直接的体现不是我写了多少行 C++，而是我能把 UI 拆成 7 个谁都不踩谁的模块、把设计取舍讲成"问题 → 决策 → 结果"让队友听懂。

我不是团队里 C++ 最强的，也不是最会画的。
但把一个想法变成能交付的功能，我大概是最快的那个——
因为这件事我已经专业地做了三年。
