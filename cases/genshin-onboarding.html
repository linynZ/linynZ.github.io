关于本拆解案的方法说明（与另外三份不同，请务必先读）

作品集另外三份拆解案的推导都建立在公开可查的游戏数据上（伤害公式、词条档位、行动值公式）。这一份不行——新手关卡最关键的指标是分环节流失率，那是厂商核心内部数据，不可能公开。任何声称"实测得到各环节流失率"的分析都不可信。

所以本文换了一套做法，把内容分成三层，并明确标注每一层的可信度：

层 内容 可信度
解析层 漏斗敏感度的数学结论（§5.1）、教学间隔判据的形式（§5.3） 不依赖任何参数，永远成立
演示层 用假设参数跑出的具体数字（哪个环节最该修） 仅为方法演示，不可作为结论引用
协议层 引导强度编码表与实录方案（§7） 供后续实录使用，产出可复现数据

这个区分不是免责声明，是本文的核心方法：拿不到数据时，仍然可以把决策规则先确定下来，等数据到位直接代入；而一个会随参数翻转的判断，在拿到真实数据前根本不该被写进结论。

1. 选题说明

新手关卡是全游戏留存压力最大的关卡：买量成本在这里回收或亏掉，且必须同时完成教学、世界观导入、核心爽点前置三件事。

选原神蒙德开场，因为它是开放世界"弱引导"教学的行业标杆，与强制式教学（传统 CRPG / MMO 的锁步引导）构成方法论对照，拆它能同时回答"教什么、什么时候教、用多强的力度教"三个核心问题。

定位说明：新手引导关卡在开发管线中通常是 demo 完成后"最后添加"的部分，展示的是留存 / 引导设计能力，而非关卡策划最值钱的"博弈性关卡"能力。因此本案在作品集中的定位是系统策划 / 引导与留存方向的证明材料。若目标岗位是关卡策划，应另做"博弈关卡拆解 + Unity 灰盒复现"（见 §9 待办）。

贯穿全案的核心区分：

  • 关卡策划的关卡：目标是"令玩家印象深刻"，允许博弈、允许失败
  • 新手引导的关卡：目标是"教会玩家"，强制、不允许失败
  • 原神开场的设计难题：用前者的外观（开放世界、可自由走动）完成后者的任务（必修教学）——本案重点拆它如何伪装强制性

2. 开幕 CG 与叙事钩子

幕 内容 设计功能
1 双子与"神"对峙、战败、分离 世界观最高冲突前置 + 长线叙事钩（找回血亲）
2 选择性别 / 命名 自我代入的最小成本仪式
3 海滩苏醒、遇派蒙 引导者角色登场（教学的"嘴"）

把最贵的 CG 放在第 0 分钟，是买量转化逻辑——广告素材与开场体验必须无缝，否则转化流失。

派蒙的本质是可对话的教学 UI：所有强制教学都通过她的台词包装成叙事，规避"系统弹窗感"。这是一个可迁移的设计模式：给教学系统一个角色身份，就能把"系统在命令你"改写成"同伴在提醒你"，力度相同而抵触感大幅下降。

3. 教学序列还原（教学埋点表）

本案核心交付物之一。[待实录] 项需重开账号按 §7 协议逐项确认。

# 教学项 触发点 教学方式 强制等级 兜底设计
1 移动 / 视角 出生即触发 屏幕按键提示浮层 软强制（不走不推进） 提示常驻直到完成
2 普攻 首组史莱姆 浮层 + 低威胁标靶 软强制 史莱姆不主动索敌

4 冲刺 / 攀爬 / 游泳 地形自然触发 情境式（遇坡教攀爬） 弱引导 体力条首次出现即教学
5 滑翔翼 剧情授予（进城前） 剧情锁 + 强制试用场景 硬强制 高台下落保证必用
6 元素视野 任务节点 任务目标绑定 硬强制 不开视野任务不推进
7 拾取 / 背包 / 地图 / 任务界面 首次获得物品 / 开图 UI 红点 + 派蒙提示 弱引导 红点持续到查看
8 元素反应 火史莱姆场景 环境预设（草地 + 火） 弱引导（可错过） 后续任务重复暴露

三点观察：

  1. 强制等级随时间递减——前 10 分钟软强制密集，进城后几乎全转为红点式弱引导。教学力度曲线与玩家"被教学容忍度"的衰减同步。
  2. 绑定式教学：教学不弹独立窗口，而是绑定在"第一次必然发生的情境"上（第一个坡教攀爬、第一次落地教滑翔）。情境即教程——这一条在 §5.3 会得到一个量化解释。
  3. 可错过的教学全部有重复暴露设计：错过第一次，后续任务场景再次预设同样的环境组合。§5.2 会说明为什么这类教学"不占环节"是关键。

4. 空间结构与节奏

     │                     │
     └── 海面（软墙：游泳体力不足即劝退）
                           ↓ 唯一出口，出口即取景框

     ↓ 黄金路线：道路 + 发光采集物 + 史莱姆点缀

     ↓
[蒙德城]（引导密度归零，进入自由探索）远景钩子：风龙废墟轮廓

4.2 空间引导手法

  • 出生点构图：睁眼第一帧就是构图完成的取景框
  • 单出口教学场：开场区域三面软墙（海、崖），保证教学期不迷路，但用自然地形而非空气墙伪装
  • 地标牵引：风神像 / 大树 / 城市剪影构成 200m / 500m / 1500m 三级视觉锚点，替代箭头导航
  • 面包屑：路径上的采集物与低威胁怪物提供微奖励节拍，维持前进动机

软墙的设计值得单独说：海面用游泳体力做边界，本质是"用系统规则代替碰撞体"。玩家撞到的不是一堵墙，而是一个可以理解的规则——边界因此不破坏世界可信度。这是开放世界引导里成本最低、效果最好的一个手法。

5. 量化分析

5.1 留存漏斗：优先该修哪个环节？

模型：玩家依次经过 n 个环节，各环节流失率 p_i，通关总留存 R = Π(1-p_i)。

产品侧常见直觉是"优先优化最早的环节，因为经过的人最多"。求偏导：

∂R/∂p_i = -Π_{j≠i}(1-p_j) = -R / (1-p_i)

这个结果与位置 i 无关，只随 p_i 单调递增。

结论一（解析层，不依赖参数）：优先该修的是流失率最高的环节，不是最早的环节。

"越早越重要"混淆了经过的人多与损失的人多。经过的人多但流失率低的环节，优化它的边际收益反而最小。

【假设演示】 用一组假设流失率跑通全流程（参数为我编的，仅演示方法）：

# 环节 流失率 累积到达 绝对流失 修复收益
1 开幕 CG 5.0% 100.0% 5.0% +1.49%
4 首战：普攻 6.0% 90.3% 5.4% +1.80%
6 攀爬 / 体力条 8.0% 81.5% 6.5% +2.46%
8 元素视野 + 任务界面 12.0% 71.2% 8.5% +3.86%
9 安柏 / 多角色切换 7.0% 62.7% 4.4% +2.13%

三种排序给出三个不同答案：按【最早】→ 开幕 CG；按【绝对流失】→ 元素视野；按【修复收益】→ 元素视野。后两者一致，"最早"是错的。

⚠️ "元素视野是最该修的环节"这个具体判断完全来自我假设它流失率 12%，换一组假设就换一个答案。它只是方法演示，不可引用为结论。 唯一可引用的是上面那条解析规则。

5.2 环节数就是留存预算

设次留目标 D、通关玩家的次留转化率 c，则需 R ≥ D/c。n 个环节均匀分摊时，单环节流失率上限：

p_max = 1 - (D/c)^(1/n)
次留目标 D 通关→次留 c 所需 R 单环节流失上限
30% 85% 35.3% 9.89%
40% 85% 47.1% 7.26%
50% 85% 58.8% 5.17%

结论二：每多加一个教学埋点，就摊薄了所有环节的容错预算。

以次留 40%、转化率 85% 为例（n=10），单环节流失率必须压到 7.3% 以下——每 14 个走到该环节的玩家里最多流失 1 个。而 p_max 随 n 增加单调下降。

这条硬约束解释了原神的两个做法：

  1. 能合并的教学一定合并——攀爬与体力条是一个环节而非两个，拾取与背包是一个环节而非两个。不是偷懒，是在省留存预算。
  2. 可错过的教学不占环节——元素反应做成"完全不理解也能过"，它就不进入这条乘法链；靠后续重复暴露补课，把教学成本从"必过关卡"转移到"长期渗透"。

由此得到一个反直觉的判据：拆解新手关卡时，"教了多少东西"是个坏指标，"占用了几个必过环节"才是好指标。前者越多越显得内容丰富，后者越多留存越差——两者方向相反。

5.3 教学与首次应用的间隔

用 Ebbinghaus 保留曲线的常用形式 R(t) = exp(-t/S)，设计判据为：教学项在首次被要求应用时保留率不低于阈值，解得最大间隔

t_max = -S · ln(R_min)

S 需按品类标定 [待实测]，此处只给判据形式。

结论三：原神的"情境即教程"本质上是把 t 压到接近 0。

原神几乎所有核心教学都绑定在第一次必然发生的情境上——遇到坡就教攀爬并立刻要爬，从高处落下就教滑翔并立刻要滑。在模型里这等价于令 t → 0，于是 R(t) → 1，遗忘曲线这一项被彻底绕开了。

对比传统 MMO 的"集中弹窗教程 + 之后自己摸索"，t 被拉到几十分钟，保留率按曲线掉到 0.3~0.5——这正是那类教学"教了等于没教"的量化解释。

所以绑定式教学的价值不在于它更不打扰玩家（那是副产品），而在于它把教学—应用间隔压到零，从根本上取消了遗忘损耗。这个原则可以直接迁移到任何教学设计。

交叉印证：按这个判据审视教学埋点表，高风险项是教学与首次真正应用间隔久的那些——元素视野、任务界面 / 背包、多角色切换。这三项恰好也是 §6 按漏斗逻辑点名的三项。 两条独立分析路径指向同一批教学点，比任何单一方法都可靠。

6. 问题分析与改进

问题 1：教学项在进城前过载。 背包 / 地图 / 任务 / 元素视野四项 UI 教学挤在同一时段，红点风暴稀释单项注意力。按 §5.2，这还占用了四份容错预算。 → 改进：非战斗类 UI 教学延后到"第一次需要时"（首次任务追踪失败时才教任务界面）。 → 成本：引导触发条件改造，低。 → 收益：减少必过环节数，直接提升 p_max。

问题 2：弱引导的代价是教学漏损。 元素反应类可错过教学依赖重复暴露，但重复暴露场景没有埋点验证玩家是否真的学会（会用 ≠ 见过）。 → 改进：给关键机制加"行为验证"式补课触发器——若玩家 N 场战斗未主动触发反应，派蒙台词补课。 → 成本：埋点 + 触发器，低，且完全不打扰已学会的玩家。

问题 3：多角色切换教学依赖单一事件。 安柏入队后若玩家不换人，弓箭机制实质未被教学，且按 §5.3 首次应用时间不可控。 → 改进：城门前空中风史莱姆做成"近战打不到"的硬情境，倒逼一次换人。 → 成本：关卡怪物配置微调，极低。

问题 4（新增，来自 §5.2）：教学项预算没有显式管理。 从设计流程看，教学项更像是"每个系统各自申请一个位置"累加而成，缺少一个统一的预算约束。 → 改进：把"必过教学环节数"设为一个显式的设计预算（如 ≤10 个），新增教学项必须先挤掉一个旧的，或论证它能与现有环节合并。 → 成本：流程约束，零开发成本。 → 理由：p_max 随 n 单调下降是硬数学约束，不做显式管理就一定会超支——而超支的后果（次留下滑）要到上线后才可见，那时改动成本最高。

7. 引导强度编码协议（为实录准备）

本章是本案的方法论交付物：把"强制等级"这类定性判断变成可复现的编码规则，使 §3 的表格能被他人独立复核。

7.1 强制等级的操作性定义

等级 判据（可观察，不依赖主观感受）
硬强制 不完成该操作，主线无法推进（任务卡住 / 场景不开门）
软强制 不完成不影响推进，但会持续提示（浮层常驻 / NPC 反复喊话）
弱引导 仅一次性提示或红点，不重复，不阻塞
可错过 无显式提示，仅环境预设；玩家可完全无感通过

编码时逐项实测：故意不做该操作，观察 60 秒，按上表归类。这样两个独立编码者应得到相同结果。

7.2 实录记录字段

每个教学项记录：序号 / 名称 / 触发时间戳 / 触发条件 / 提示形式 / 强制等级 / 首次应用时间戳 / 教学—应用间隔。

最后一列直接喂给 §5.3 的判据。

8. 技术实现推断

  1. 引导系统架构：教学项推断为数据表驱动的 tutorial entry（触发条件 / 展示形式 / 完成条件 / 优先级），运行时是一个带互斥锁的引导队列——同屏只出一条浮层，解释了教学项的排队现象。
  2. 触发器形态：情境式教学 = trigger volume + 状态条件（体力条首次可见 = 进入消耗状态，而非进入区域）；剧情锁教学 = quest graph 节点后挂载。
  3. 软墙实现：海面用游泳体力做软墙，本质是"用系统规则代替碰撞体"——引导用的地形约束尽量不用空气墙，保开放世界可信度。
  4. 埋点结构：新手期每个教学项必有 funnel 埋点（触发 / 完成 / 耗时），次留归因靠它。

面试可展开的问题：「如果你是策划，看什么数据判断新手关卡健康度？」 我的答案基于 §5：不是看总通关率，而是看各环节流失率的分布。总通关率只告诉你有没有问题，分布才告诉你问题在哪；而按 §5.1，应该优先修流失率最高的环节而非最早的环节。再叠加 §5.3 的教学—应用间隔，可以在拿到流失数据前就预判哪些教学点高风险。

9. 本案的局限与后续

局限：本案是四份拆解案里唯一无法用公开数据支撑核心指标的。§5 的解析结论可靠，具体数字全部是演示。这是选题决定的，不是方法问题——但必须说清楚，否则就是拿假设冒充数据。

后续：

  1. 按 §7 协议完成实录，把演示层换成实测层（教学—应用间隔可以真实测量，流失率不能）
  2. 若目标岗位是关卡策划而非系统 / 引导策划，另做一份"博弈性关卡拆解 + Unity 灰盒复现"——那才是关卡策划能力的直接证明。我有 Unity 工程能力（见 ChronoTraveler 项目），灰盒复现对我是低成本高说服力的选项
