2. 设计目标与体验目标

一句话核心体验：潜行 = 信息战 + 空间博弈——玩家变强不是因为数值高，而是"信息多 + 判断准 + 操作稳"。（本人在头脑风暴阶段提出并写入团队设计文档）

目标 来源约束 落地规则
道具是"操纵注意力"的手段，不是伤害来源 课程硬约束：核心玩法必须非暴力 道具（Gadget）一律不造成伤害，只影响敌人视野/移动/信息；武器（Weapon）默认锁定，须在图内拾取解锁
让"不被发现"成为得分最优解 团队设计原则"重点在操纵敌人注意力" 积分纯扣减制：击杀、用道具、耗时、触发倒计时全部扣分，唯一的加分方式是"不做这些"
一命通关的压力要可读 团队定义：倒计时不可暂停/重置 警戒条四段色 + 倒计时触发即扣分并弹通知 + 评级实时降级提示
出发前的配装是决策，不是仪式 团队规则"同时仅可携带两种" 道具 2 槽 + 武器 2 槽，进图后由轮盘切换；库存开局扣减、通关才回库

3. 系统概述与使用循环

道具系统的核心状态只有一份：Res_ItemInventory2（5 个 ItemSlot：携带数 / 仓库数 / 解锁 / 冷却时长）。所有 UI（HUD 双面板、轮盘、背包、配装页）都是它的纯消费者，通过 Res_GameState.itemSlots/weaponSlots 显示槽同步（ItemEquipSync）。

[主菜单·配装 MissionSelect]
  ITEMS(MAX 2) / WEAPONS(MAX 2) 两栏 → 写入 missionEquippedItems/Weapons
        │  OnRoundStart：Gadget 携带 = min(maxCarry, 仓库)，仓库同步扣减；
        │                Weapon 已解锁则补满 2，未解锁为 0
        ▼
[进图]  SyncEquipmentToGameState → HUD 槽位；无配装场景 AutoFillHUDSlots 兜底
        │
        ├─ 拾取：靠近 2m（XZ）→ Evt_Item_Pickup → 携带+1（≥上限则拒绝）
        │        武器首次拾取 = 永久解锁 + 补满 → "UNLOCKED" 通知
        ├─ 切换：长按 TAB 开 4 扇区轮盘（左道具 / 右武器），松手落选为活跃槽
        ├─ 使用：Q = 当前道具槽，E = 当前武器槽 → 冷却检查 → 携带−1 → Evt_Item_Use
        │        → 显示槽 cooldown=1.0 按 cooldownDuration 线性归零；面板闪光 0.3s
        │        → 积分 −5（Sys_ItemEffects），武器击杀另计 −10
        ▼
[关卡完成 NextLevel]  携带数 + 警戒度 快照到 Res_UIState → 下一图恢复（跳过 OnRoundStart）
        ▼
[战役结束 OnRoundEnd]  通关：Gadget 剩余回库（≤maxStore）；失败：丢失。武器一律清零不回库
        ▼
[存档 autosave.save v3]  itemId + storeCount + unlocked

4. 道具/装备规则详述

4.1 分类与数量规则

规则 团队文档定义 代码落地（Res_ItemInventory2.h） 归属
分类 道具=不造成伤害；武器=造成伤害 ItemType::Gadget / Weapon，GetItemType(id) 集中查询 团队设计 / 本人集中化
携带上限 各道具独立上限（1–5） Gadget kGadgetMaxCarry = 99，Weapon kWeaponMaxCarry = 2 团队设计，本人调整（见 §9）
库存上限 各道具独立（1–99） Gadget maxStore = 99，Weapon maxStore = 0（不入库） 团队设计，本人实现
开局扣减 库存 = 库存 − 携带 OnRoundStart()：Gadget 取 min(maxCarry, storeCount) 并扣库 团队设计，队友 A / 本人实现
结算回库 库存 = 库存 + 携带，超上限遗失 OnRoundEnd(isVictory)：仅通关回库并钳到 maxStore；武器清零 团队设计，本人加"仅通关回库"分支
满携禁拾 携带=上限时禁用拾取 CanPickup()；DetectPickup 跳过并留日志 团队设计，本人实现
图内生成上限 — mapPickupMax = 99（0 = 不生成） 本人

配装页限制：ITEMS (MAX 2) / WEAPONS (MAX 2) 两栏，未解锁武器不显示；菜单阶段无库存资源时用默认实例 + 存档缓存 savedStoreCount/savedUnlocked 回填。

4.2 快捷键与径向轮盘（Res_InputConfig / UI_ItemWheel / Sys_UI）

键 功能
Q 使用当前活跃道具槽
E 使用当前活跃武器槽
F CQC 近身制服
G 伪装（原 E，因 E 让给武器而迁移）
TAB 长按 开轮盘；松手确认
I 背包（4×3 网格，可直接装备/卸装到 HUD 槽）

轮盘：居中于游戏视区（屏宽减去右侧聊天面板），外径 120 px / 内径 40 px，扇区 0/1 = 武器槽（右半）、2/3 = 道具槽（左半）；鼠标离中心 > 20 px 时按 atan2 角度落扇区并高亮，活跃槽橙色粗弧，各扇区显示名称与实时携带数；开启时显示系统光标并暂停相机旋转。轮盘只切活跃槽、不直接使用，对应团队规则"一次只用一种道具 + 一种武器"，也避免误触。

4.3 独立冷却

每种道具自带 cooldownDuration：HoloBait 3 s、DDoS 8 s、RoamAI 5 s、TargetStrike 10 s、RadarMap 10 s（= 小地图激活时长）。使用时显示槽 cooldown = 1.0，每帧按 dt / duration 递减；冷却中按键被拒绝；HUD 面板显示 READY/WAIT + 进度条，使用瞬间边框闪光 0.3 s。

4.4 地图内生成点（数据驱动 + 可行走面吸附）

MapLoader 第 9 步读取地图配置指向的 .itemspawns（ItemSpawnLoader::LoadItemSpawns），逐条 PrefabFactory::CreateItemPickup：武器用胶囊体 fallback、道具用立方体，按道具类型着色并自发光（emissiveStrength = 2.0），绕 Y 轴旋转（90°/s）便于发现；已在存档中解锁的武器不再生成。GameplayBootstrap 加载 NavMesh 后对所有拾取实体 SnapToNavMesh（最近边投影 fallback，替代早期的重心 fallback），Y 加 pickupSnapYOffset，杜绝浮空/穿地。

4.5 拾取与解锁通知

  • 拾取半径 2.0 m（XZ 平面，不依赖物理 Trigger）；每个生成点带 quantity，逐个入包，耗尽销毁实体；播放 ItemPickup 音效。
  • 通知走 PushActionNotify：PICKED UP <名称>；武器首拾 UNLOCKED <名称>（3 s）。
  • 拾取后若 HUD 对应类型槽位为空，自动填入。

4.6 跨关卡持久化（PR #72）

战役 = 5 图池随机取 3（HangerA / HangerB / Helipad / Lab / Dock）。NextLevel 时 Main.cpp 把 alertLevel 和 5 项 carriedCount 快照到 Res_UIState.campaignAlertLevel / campaignCarried[5] 并置 campaignContinue = true；下一图 OnEnter 恢复后置回 false 并跳过 OnRoundStart（避免二次扣库）。static_assert 保证快照数组覆盖 kItemCount。

6. 战役积分与评级（PR #59）

6.1 逐动作计分规则（Res_ScoreConfig 默认值，纯扣减制）

事件 触发点 分值 备注
战役开始 ResetCampaignScore 初始 1000 三关共享一份分数
时间流逝 Sys_UI（仅 HUD 画面，暂停不计） −1 / s 子秒累加器，分数 > 0 时才扣
击杀敌人 CQC / TargetStrike / RoamAI / 通用 hp≤0 −10 / 次 四条路径统一走 Sys_DeathJudgment 死亡流程，已死目标不重复计
使用道具 Sys_ItemEffects 收到 Evt_Item_Use −5 / 次 含道具与武器的"使用"本身
警戒满触发倒计时 Sys_Countdown −200（每关一次） 通知 ALERT SURGE / COUNTDOWN
倒计时耗尽 / 被抓捕 Sys_Countdown / Sys_DeathJudgment −500（每关一次） 通知 MISSION FAILED
及格线 Sys_LevelGoal 终关结算分 > 500 才算通关 分数不足即使到达终点也判 INSUFFICIENT SCORE

每次扣分同时写入分项 scoreLost_time / kills / items / countdown / failure 与计数 scoreKillCount / scoreItemUseCount，供结算明细。

6.2 评级阈值（GetScoreRating）

分数 ≤500 501–599 600–699 700–799 800–899 900–949 950–969 ≥970
评级 F D C B A S SS SSS

每帧比较档位，降级时弹 RATING DROP S > A 通知——玩家在关内就能感知"这次击杀让我掉了一档"。

6.3 跨关累积与重置

  • campaignScore 存于 Session 级 Res_UIState，三关连续扣减；NextLevel 只重置两个"每关一次"惩罚标记，不重置分数。
  • StartGame / 返回主菜单 / 重开 调用 ResetCampaignScore 归零所有分项。
  • 多人模式复用同一套规则，终局按 > passThreshold 判胜/败。

6.4 结算界面

Victory（CAMPAIGN COMPLETE）：TOTAL TIME、CLEARED MAPS 三行、FINAL SCORE: N [评级]（评级色）+ BREAKDOWN：TIME (−1/s)、KILLS (×n)、ITEMS (×n)、COUNTDOWN，扣分项统一用独立"扣减红"。GameOver 页额外显示 FAILURE 行，并对"通关但 ≤500"改标题为 MISSION FAILED / INSUFFICIENT SCORE。

6.5 设计意图

  • 潜行是唯一最优策略：满分只能靠"少做事"守住；击杀 −10 看似便宜，但 SSS 只容 30 分损耗，一次击杀或三次道具即掉档。
  • 击杀有代价但不禁止：非暴力不靠禁用武器，而是让武器"贵"——默认锁定 + 图内拾取 + 携带 2 + 击杀扣分。
  • 时间压力来自分数而非警戒条：−1/s 让玩家不敢无限蹲守，形成"等待 vs 冒险"的持续博弈。

10. 设计取舍与局限

  • 13 项道具只实装 5 项：受周期与"评分以编程为主"限制，保留覆盖"视野 / 移动 / 信息 / 销毁"四类的最小集合；纸箱、对话类插件未实装。
  • 扣减制的代价：数字只往下走、反馈直观，但"完美通关 = 什么都不做"略显消极；可补"未触发倒计时通关 +N"的正向奖励。
  • 携带上限 99 事实上取消了 Gadget 携带约束：为拾取体验让步，代价是配装页的携带数决策变弱。
  • 积分常量仍是编译期默认值：未接 JSON 热调，平衡需重新编译。
  • 无自动化测试：靠 static_assert、边界守卫与 5 轮 PR 审查保证。
