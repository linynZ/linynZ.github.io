1. 为什么拆这个系统

《鸣潮》与同赛道产品在战斗上最核心的差异不是动作手感，而是把「切人」从一个功能操作升级成了资源系统。

原神的角色切换是无成本的（仅共享冷却），绝区零用连携技做强制演出切换，而鸣潮的协奏值让「什么时候切、切给谁」变成一个需要提前规划的资源决策。一个机制同时撬动三层设计目标：

  • 局内：切人时机成为操作深度的一部分
  • 局外：延奏增益的指向性决定配队构筑
  • 商业：角色之间的增益耦合，是「套装式卖角色」的数值杠杆

一个系统吃三层目标，值得拆到底。而支撑它的乘区结构，又暴露了库洛在数值设计上的几个明确取舍——那是本文后半程的重点。

4. 数值层深拆：从乘区结构反推设计意图

这一章是本拆解案的主体。所有小节的结论都可由附录脚本复现。

4.0 乘区结构（公开原材料）

总伤害 = 基数区 × 倍率区 × 增伤区 × 加深区 × 暴击区 × 防御区 × 抗性区

区内加算、区间乘算。关键常量：基础暴击率 5%，基础暴击伤害 150%。

暴击期望乘区：E = CR·CD + (1 - CR)，等价写成 E = 1 + CR·(CD - 1)。后一种写法是下面推导的起点——它把问题化成了一个乘积最大化问题。

4.1 双爆最优配比：解析解

建模。 记 D = CD - 1（超出非暴击部分的净暴伤），则 E = 1 + CR·D。

一条副词条的平均贡献是暴击率 +8.40% 或暴击伤害 +16.80%，比值恰为 2。因此可以定义一个统一的「词条预算」B（以暴击率当量计），把它拆给两边：

CR = CR₀ + x
D  = D₀ + 2(B - x)

求解。

E(x) = 1 + (CR₀ + x)·(D₀ + 2B - 2x)
dE/dx = (D₀ + 2B - 2x) - 2(CR₀ + x) = 0
   ⟹  D* = 2·CR*
d²E/dx² = -4 < 0   （极大值）

结论一：CD - 1 = 2 × CR 时暴击乘区取极大。

这就是社区口口相传的「双爆 1:2」。本文给出的是它的数学出处，而不是又一次复述经验法则。注意成立前提：它依赖「一条暴伤词条 = 两条暴击率词条」这个档位设计——换一款档位比不是 2 的游戏，这条经验立刻失效。

数值验证（预算 B = 8 条暴击率当量）：

给暴击率的条数 CR CD 暴击乘区 E D/CR
0 0.0500 2.8440 1.09220 36.88
3 0.3020 2.3400 1.40468 4.44
4 0.3860 2.1720 1.45239 3.04
5 0.4700 2.0040 1.47188 2.14
6 0.5540 1.8360 1.46314 1.51
8 0.7220 1.5000 1.36100 0.69

数值最优落在第 5 条，解析最优点 CR* = 0.4860 / CD* = 1.9720，比值 2.0000。两者一致。

4.2 「1:2」的失效边界

上面是内点解，它默认 CR 可以自由取值。但暴击率封顶 100%，一旦最优解要求 CR* > 1，问题退化为角点解，此时正确策略是全部给暴伤，「1:2」反而是错的。

令 CR* = 100% 解出临界预算：B_c = 1.70 暴击率当量。

纯靠副词条堆到这个量级并不现实，但外部暴击率来源会抬高 CR₀，让角点解提前触发。演示（角色已从武器与共鸣链拿到 +40% 暴击率）：

给暴击率的条数 CR（钳制后） CD 暴击乘区 E
2 0.6180 2.5080 1.93194
3 0.7020 2.3400 1.94068
4 0.7860 2.1720 1.92119
7 1.0000 ← 溢出 1.6680 1.66800

结论二：最优配比随外部暴击率来源向「全暴伤」迁移。（无外部来源时最优 5 条，+40% 时降到 3 条）

这解释了玩家侧一个常见困惑：为什么某些角色的推荐配装明显偏离 1:2。不是攻略互相矛盾，是两份攻略站在约束的不同侧——一份在讨论内点解，另一份的角色已经接近角点。

策划视角的读法：一个「所有人都能背下来的配装口诀」，如果它的成立条件依赖于玩家还没有的资源，那么随着版本推进（武器池、共鸣链普及），这条口诀会自然失效，而多数玩家不会意识到。这是数值设计里一种隐蔽的知识贬值，做长线运营时需要主动预判并通过官方内容重新校准玩家认知。

4.3 档位比 2:1 是认知成本设计

词条 区间 中值
暴击率 6.3% ~ 10.5% 8.40%
暴击伤害 12.6% ~ 21.0% 16.80%

下界比、上界比、中值比三个都精确等于 2.0000。不可能是巧合。

结论三：档位比被钉死在 2:1，是为了让社区评分公式 CV = 暴击率×2 + 暴击伤害 成为一个线性可加、跨词条可比的标量。

推导顺序应该是这样的：先由 §4.1 得到最优条件 D = 2·CR，再把档位比设成同样的 2:1。于是「堆 CV」这个极简心智模型在最优解附近始终指向正确方向。玩家不需要理解乘区结构，只要会加法，就能把装备练对——一个数值优化问题被降维成了一次心算。

但 CV 有它的边界，这一点多数攻略文没有讲清楚。固定预算下改变配比，CV 恒为 1.9440 不变，实际收益却在 74.20% ~ 100% 之间浮动：

配置 CV 暴击乘区 E 相对最优
0 暴击率 + 8 暴伤 1.9440 1.09220 74.20%
3 暴击率 + 5 暴伤 1.9440 1.40468 95.43%
5 暴击率 + 3 暴伤 1.9440 1.47188 100.00%
8 暴击率 + 0 暴伤 1.9440 1.36100 92.47%

CV 是总量指标，不是配比指标。 它能回答「这个声骸值不值得练」，回答不了「下一条词条该要什么」。后者需要 §4.7 的边际分析。

与原神的对照：原神同样是 1:2 双爆结构，但强化次数随机分配到 4 条词条中的任意一条，单个圣遗物的最终价值在获得时无法预判。鸣潮把随机性收敛在「出不出这条词条」而非「这条词条被强化几次」——副作用是声骸的价值可以在掉落瞬间判定完毕。这直接支撑了它「刷取快、判定快、弃置快」的养成节奏，与 §4.6 的结论互为印证。

4.4 抗性分段函数：连续性验证与系数反解

公开规则：

R < 0        :  mult = 1 - R/2
0 ≤ R < 0.8  :  mult = 1 - R
R ≥ 0.8      :  mult = 1 / (1 + 5R)

分段函数是数值设计最容易出事故的地方，先验证连续性：

拐点 左极限 右极限 结论
R = 0.0 1.000000 1.000000 连续
R = 0.8 0.200000 0.200000 连续

两个拐点都连续。 进一步，高抗段的系数 5 并非自由参数：

设高抗段为 1/(1+kR)，要求它在 R = 0.8 处接上中段的 1 - R = 0.2：

1 / (1 + 0.8k) = 0.2  ⟹  1 + 0.8k = 5  ⟹  k = 5

结论四：k = 5 被连续性条件唯一确定，无自由度。 这说明设计流程是「先定拐点 0.8 与中段线性式，再解出高抗段系数」，而不是三段各自调参。这是一个能从公开数字反推出来的实现细节。

一阶导不连续，三段斜率对应三种意图：

段 斜率 设计意图
负抗段 −0.5 减抗收益打对折。R 从 0 打到 −100% 只拿到 ×1.50 而非 ×2.00——对「减抗流」配队的软性衰减，防止减抗成为无脑最优解
中段 −1.0 玩家直觉区。「敌人 20% 抗性 = 少 20% 伤害」，所见即所得
高抗段 −0.2（在拐点处） 双曲衰减，倍率恒为正，敌人永不免疫

高抗段是一道数值安全阀：R = 200% 时仍有 ×0.0909，R = 1000% 时 ×0.0196。设计师因此可以放心给后期敌人堆高抗做检查点，不必担心某个抗性数字把玩家伤害归零造成不可通关的死局。

实战锚点：大世界怪物基础全抗 10%，对应属性怪额外 +30%（合计 40%）。代入中段，打对应属性怪的倍率 0.60，相对打普通怪的 0.90 少 33.3%。

这就是「属性队打同属性怪反而吃亏」的数值来源，也是驱动玩家养多队而非一队通吃的经济杠杆——直接服务角色卡池的宽度消费。抗性设计在这里不是平衡工具，是商业工具。

4.5 防御区：一个我自己推翻的假设

本拆解案初稿写下过这样一句：

「鸣潮的等级压制显著温和于原神，因此把门槛从练度转移到了操作。」

落笔前把两个公式并排代入，结论被自己证伪：

鸣潮 ≈ (100 + L_角色) / (199 + L_怪物 + L_角色)
原神 =  (100 + L_角色) / (200 + L_怪物 + L_角色)

分母只差 1。 逐点验证（角色 90 级）：

怪物等级 等级差 鸣潮 原神 差值
80 −10 0.5149 0.5135 0.00139
90 ±0 0.5013 0.5000 0.00132
100 +10 0.4884 0.4872 0.00125
120 +30 0.4645 0.4634 0.00113

两条曲线最大偏差 0.147 个百分点。每级衰减：鸣潮 −0.263%，原神 −0.262%。

结论五（否定性）：防御乘区是两家共享的行业标准解，等级压制强度实质相同——这里没有产品差异化。

这个否定性结论有两点用处：

（1）纠正一个流行的归因错误。 玩家常把越级挑战的吃力归咎于「等级压制」，但防御区在两款产品里都温和到可以忽略（±10 级只有约 ±2.5% 的伤害摆动）。真正的练度门槛来自另外两处：角色等级带来的攻击力面板成长（进入基数区，乘区里权重最大的一项），以及敌人血量随等级的成长（根本不在伤害公式内，但直接决定击杀所需时间）。做数值时若混淆这三者，会把参数调在错误的旋钮上。

（2）反向界定了差异化的真实位置。 既然防御区是抄作业式共享的，鸣潮与同赛道产品的区别必然落在别处——从本文其余章节看，落在抗性段函数的钳制方式（§4.4）、随机性在养成链上的位置（§4.6）、以及协奏值把切人资源化（§5）。这三处才值得展开。

方法论备注：拆解案里敢于写「这里没有特殊设计」，比给每个数字都硬编一个设计意图更接近真实的策划工作。数值系统里存在大量行业沿用解，识别出哪些是沿用、哪些是选择，本身就是拆解能力的一部分。

附带产出——无视防御的乘区错位收益。 由简化式反解出 90 级怪物等效防御约 1512：

无视防御 防御乘区 等效增伤
10% 0.5276 +5.25%
20% 0.5569 +11.08%
50% 0.6678 +33.22%

无视防御 20% ≈ 增伤 11%，且它独占防御区、不与增伤区抢加算池。对已经堆满增伤的成型队，一件带无视防御的效果价值高于同等数字的伤害加成。这是评估辅助角色与武器时容易被忽略的收益，也是「乘区错位」这个概念的实际用途。

4.6 声骸：随机性预算被放在筛选而非强化

建模假设 [实测校验项]：副词条池按社区通行的 13 种建模；5 条副词条互不重复，因此是不放回抽样，服从超几何分布——而非许多攻略默认的二项分布（后者会系统性高估双爆同出概率）。本节按等概率建模求上界，实测概率非均匀时结论只会更差。

双爆命中分布：

k（5 条中的双爆条数） 组合数 概率
0 462 35.90%
1 660 51.28%
2 165 12.82%

双爆同出概率 12.82%，期望 7.8 个声骸出 1 个。

4C 毕业件的期望成本，需同时满足套装正确、主词条命中双爆之一、副词条含另一个双爆：

P = (1/5) × (2/6) × 0.4167 = 0.02778   ⟹  期望 36 件

若再要求两条双爆的档位均落在 8 档中的高 3 档，概率乘 (3/8)² = 0.1406，期望 256 件。

结论六：随机性预算被刻意压在「筛选」环节，而非「强化」环节。

声骸不能重洗、不能定向强化，随机性 100% 在掉落瞬间结算完毕。这带来一个反直觉的体验优势：沉没成本为零。玩家看一眼副词条就能当场判弃，不会像强化制那样陷入「已经投进去了，只好继续赌」的心理陷阱。

代价是刷取次数方差极大（上面的期望值背后是长尾分布），所以库洛必须用另外两个设计兜底：

  • 声骸掉落绑定大世界怪物、刷取无体力硬门槛 → 把「次数」变便宜
  • 数据坞「吸收即可合成」 → 把保底做在合成侧而非强化侧

三者是一套的：不可重洗 → 必须高频刷 → 必须去掉刷取摩擦。单看任何一条都会误判为设计缺陷，合起来看才是完整的成本结构。 拆解时孤立评价某个机制「反人类」，通常意味着还没找到与它配对的那个补偿设计。

4.7 边际收益敏感度：词条优先级是面板的函数

固定其余乘区，比较单条词条带来的总伤害相对增量。注意三者落在互相乘算的不同乘区（攻击力→基数区、伤害加成→增伤区、双爆→暴击区），因此边际收益取决于各自区内的存量：

场景 CR CD Δ暴击率 Δ暴伤 Δ攻击力 Δ增伤 最优
裸装新号 0.05 1.50 4.10% 0.82% 8.60% 8.60% 攻击力
成长期 0.35 1.80 5.25% 4.59% 5.38% 6.62% 增伤
成型队 0.65 2.20 5.66% 6.13% 3.91% 5.37% 暴伤
满配毕业 0.80 2.60 5.89% 5.89% 3.31% 4.53% 暴伤
暴击率溢出 0.95 2.40 3.00% 6.85% 3.58% 4.78% 暴伤

结论七：攻略通行的「暴击率 > 暴击伤害 > 攻击% ≈ 增伤」是一个平均意义上的近似，只在成长期区间成立。

  • 裸装期真正的最优是攻击力与增伤，不是双爆（基础暴击率 5% 时，暴伤几乎没有载体）
  • 成型后最优项随双爆存量迁移
  • 暴击率接近封顶时，它的边际收益断崖式下跌（4.10% → 3.00%）
  • 攻击力与增伤的边际收益只取决于各自区内存量，与双爆无关——乘区结构天然奖励均衡，任何单区堆到极端都是次优解

策划视角的读法：这套乘区设计把配装变成了一个每个人答案都不同的局部优化问题，而不是一张可以直接抄的标准答案表。攻略的价值因此被从「给答案」推向「给方法」，社区讨论的生命周期被拉长。这是数值结构对社区生态的隐性影响，多数拆解只讨论数值平衡，很少讨论这一层。

5. 深拆：协奏值 — 变奏 / 延奏体系

回到本文开篇的那个机制。有了 §4 的数值背景，可以看得更清楚。

5.1 规则还原

协奏值获取（0~100，每个场上角色独立持有）：

规则 状态
造成伤害、完美闪避、弹反均可积累 公开确认
不受共鸣效率影响（与共鸣能量分离的独立资源） 公开确认
仅场上角色获得 公开确认
只在触发变奏 / 延奏时清空，普通切换不消耗 公开确认
变奏 / 延奏无冷却 公开确认
各动作的具体收益值 [实测校验项] 见 §9

触发规则：协奏值满 100 时切人 → 离场角色释放延奏技能，入场角色释放变奏技能并消耗全部协奏值。未满时切人为普通切换，仅共享切人冷却。

延奏增益的三种类型（决定配队逻辑的核心）：

类型 效果 设计意图
伤害深化 下一角色某技能类型伤害加深 X% 落在独立的加深区，不与增伤区抢加算池 → 收益不随主 C 增伤堆叠而衰减 → 绑定固定搭档的价值被锁死
属性伤害加成 全队 / 下一角色某属性伤害提升 落在增伤区，与主 C 自身增伤加算 → 存在收益递减 → 拉动同属性队成型
资源 / 回复 治疗、回能 生存位的轮换价值

这里可以接上 §4.7 的乘区分析：「伤害深化」之所以比「属性加成」更值钱，不是因为数字更大，而是因为它落在一个几乎没人堆的独立乘区里。 增伤区在成型队里已经堆到 +60% 以上，再加 15% 只有约 9% 的实际收益；而加深区几乎是空的，同样 15% 就是接近满额的 15%。

这个乘区错位是延奏增益能长期保值的结构性原因——也意味着库洛可以持续售卖「深化型辅助」而不引发数值膨胀，因为它们占的是一个专用池子。

设计目的推断：延奏增益几乎都指向「下一个登场角色」而非全队常驻，这强制玩家规划切人顺序（操作深度），同时让辅助角色的价值只有在特定主 C 身上才能完全兑现。角色之间的价值耦合，是二游「套装式卖角色」的数值杠杆——买了辅助的人会想补主 C，反之亦然。

5.2 时序拆解（Technical Designer 视角）

以「满协奏切人」为例的事件序列：

[前台A] 攻击命中 → 协奏值 +X → UI 环形条满（视觉 + 音效提示）
[玩家]  按下切人键 (1/2/3)
[系统]  t0    : 冻结 A 输入 → 播放延奏技能（后台结算，不占场上时间）
        t0+Δ : 角色 B 以变奏动画登场（带位移吸附至目标）
        t0+Δ : B 获得短无敌窗口
[结算]  A 的延奏 buff 挂到 B 身上（来源者已离场，buff 仍存续）

两个可在面试中展开的技术点：

  1. 变奏登场可以取消前台角色的后摇。 切人本质上是一个全队共享的「取消窗口」资源，高手用它做动画取消（swap-cancel）。设计上没有禁止，说明官方接受它成为操作上限的一部分——这与 §2 提到的「同一套内容对不同水平玩家呈现不同难度」是同一个手法。
  2. 延奏 buff 的持有者与来源者分离。 要求 buff 系统支持离场角色的持续结算，且目标是「下一个登场角色」的延迟绑定。推断存在一个 TeamContext 层的 buff 容器，而非把 buff 挂在角色实体上。对比原神：多数后台机制依附于元素实体（场上残留物），鸣潮直接做在 buff 层——这也解释了为什么鸣潮的后台角色几乎不需要「站场时间」，而原神的后台机制大量依赖持续存在的场上实体。

5.3 与竞品的机制对照

维度 鸣潮（协奏体系） 原神（元素反应） 绝区零（连携 / 失衡）
切人成本 资源化（协奏值） 仅冷却 演出化（连携技）
队伍耦合点 延奏增益的指向性 元素反应组合 属性 / 阵营套装加成
操作上限来源 切人取消 / 弹反 / 闪反 元素编排与站场轴 极限支援 / 完美闪避
后台角色参与 延奏 buff（TeamContext 层） 元素附着残留（场上实体） 支援突击待机
增益的乘区位置 深化型独占加深区 增伤 / 反应系数区 属性加成区

三者在解决同一个问题：「3 人编队但场上只有 1 人」时，如何让另外 2 人持续产生存在感。 鸣潮的答案是把存在感做进切换动作本身，并且给它开了一个专属乘区来保证长期保值。

6. 亮点与问题

亮点

  1. 协奏值把「切人时机」从习惯变成决策，轮换轴有明确的构筑感——轴就是资源规划问题的解。
  2. 延奏后台结算不占场上时间，爆发窗口紧凑，战斗节奏显著快于同类。
  3. 操作技巧全部是增益型而非门槛型：不会弹反只是慢，会弹反有明确爽点。配合 §4.5 的发现（等级压制温和），鸣潮确实把难度压在操作上——只是这个效果不来自防御区，而来自敌人的行为设计与容错窗口。
  4. 深化型增益的独立乘区是一个漂亮的长线设计：既让辅助角色保值，又给未来的数值扩张留出了不冲突的空间。

问题与改进

问题 1：协奏值完全不透明。 获取规则游戏内零说明，普通玩家无法理解「为什么这次切人没有变奏」。现有反馈只有角色头像上的环形条，战斗中注意力覆盖不到。 → 改进：切人键位上做协奏进度的常驻可视化，满值时给键位描边高亮。 → 成本：纯 UI 层改动，低。 → 风险：增加 HUD 信息密度，需与美术确认视觉噪音。

问题 2：延奏指向性造成配队僵化。 深化类延奏把搭档关系写死（「共鸣技能伤害深化」只服务技能型主 C），版本末期表现为「一 C 一专属辅」的组合垄断。§4.7 的分析说明这不是玩家保守，而是乘区结构决定的最优解确实唯一。 → 改进：延奏效果做双轨——保留指向性增益（高数值），追加一个弱化的全队常驻增益（低数值）。前者维持耦合卖点，后者给杂交队留活口。 → 成本：数值重平衡，中。需要重新评估所有现存延奏角色。 → 权衡：会稀释「专属搭档」的商业价值，是一个明确的收入 vs 体验取舍，需要由数值与商业化共同拍板。

问题 3：切人冷却与受击打断的挫败感。 [实测校验项] 被打断连段后切人进入冷却，玩家在高压 BOSS 战中容易陷入「无操作可做」的空窗。需实测确认受击是否重置切人 CD。 → 改进：若确认为重置，改为受击硬直期间 CD 照常倒计时（而非冻结），让玩家出硬直即可行动。 → 成本：低。 → 理由：挫败感的来源不是「被打」，是「被打完还要再等」——两段惩罚叠加。

问题 4（新增，来自 §4.2）：配装知识随版本自然贬值。 「双爆 1:2」在角色获得外部暴击率来源后失效，但玩家不会察觉口诀已经过期。 → 改进：角色养成界面内置一个轻量的边际收益提示（「当前面板下，下一条词条建议优先：暴击伤害」），把 §4.7 的计算做成产品功能。 → 成本：中。需要一个客户端侧的实时计算模块，但公式全部已知，无服务端依赖。 → 收益：降低新玩家的养成试错成本，同时把攻略站的一部分流量收回站内。

7. 技术实现推断

本章为与纯策划拆解的差异点，展示「能与程序对话的策划」。

  1. 角色状态机：变奏登场是一次跨角色的状态迁移——A.AnyState → Swap（带延奏结算钩子） → B.IntroSkill。切人取消意味着 Swap 迁移的优先级高于大部分动作状态的 exit time，推断状态机对「可取消窗口」做了逐动作标记（类似动作游戏的 cancel table）。
  2. Buff 系统：延奏 buff 需要支持来源角色离场后继续 tick，且目标为「下一个登场角色」的延迟绑定。推断 buff 容器挂在 TeamContext 而非角色实体上。§4.0 的乘区结构进一步要求 buff 携带「所属乘区」标签，否则无法正确区分加深与增伤。
  3. 乘区的实现形态：区内加算、区间乘算的结构，最自然的实现是每个乘区一个累加器，结算时遍历乘算。加深区几乎只被延奏与声骸技能写入——这也从工程侧印证了 §5.1 的判断：它是一个被刻意留空的专用池。
  4. 输入缓冲：切人键在动作后摇中按下能被缓冲执行 [实测校验项]，动作游戏标配。验证方法为逐帧录屏统计按键到响应的帧差。
  5. 协奏值的服务端校验：协奏收益逐动作结算且与伤害挂钩，推断为服务端权威 + 客户端预表现。PC 端断网测试可验证表现层与结算层是否分离。

8. 结论

拆完这一轮，我认为鸣潮战斗系统的设计骨架可以概括成三句话：

  1. 把切人资源化，让 3 人编队里的另外 2 人通过「切换动作本身」产生存在感，并用一个独立乘区保证这份存在感长期不贬值。
  2. 把随机性放在筛选而非强化，用零沉没成本换取高方差，再用「刷取无摩擦」与「合成侧保底」兜住方差。
  3. 把难度压在操作而非练度——但这不是通过等级压制实现的（§4.5 证伪），而是通过敌人行为设计与容错窗口。

值得学习的是第 1 点里的乘区留白手法：预留一个几乎没人堆的独立乘区，专门用来承载未来要卖的东西。它同时解决了「新角色必须更强」与「数值不能膨胀」这对矛盾——新内容占用的是空池子，不与存量竞争。这个思路可以迁移到任何有长线角色投放压力的产品上。

9. 实测校验计划

本文的定量结论分两类：由公开公式严格推导的（§4.1–4.5、4.7）无需实测，代入即可复核；依赖建模假设的（§4.6）与规则未公开的（§5.1 具体数值）需要实测。

实验 A：副词条概率分布校验（校验 §4.6）

  • 目的：验证 13 种副词条等概率假设是否成立
  • 方法：连续采集 200 件以上 4C 声骸的副词条，统计各词条出现频次
  • 判据：卡方检验，若 p < 0.05 则拒绝等概率假设，改用实测频率重算 §4.6 的期望件数
  • 预期：等概率假设很可能被拒绝（多数同类产品会给主流词条降权），实测结果将使毕业成本高于本文的 36 / 256 件

实验 B：加深区独立性验证（校验 §5.1 的核心论断）

  • 目的：确认「伤害深化」确为独立乘区，而非加算进增伤区
  • 方法：固定角色 / 武器 / 声骸，对训练场木桩打同一段技能，分别记录有 / 无延奏深化 buff 时的伤害
  • 判据：若伤害比值恰等于 (1 + 深化%)，则为独立乘区；若显著小于该值，则为加算
  • 意义：这是 §5.1、§6 亮点 4、§8 结论 1 共同依赖的前提，优先级最高

实验 C：协奏值收益表（补全 §5.1）

  • 方法：逐动作记录协奏环增量，录屏 + UI 像素测量，或以「打满 100 所需动作数」反推
  • 采样：至少 2 个角色对照，确认收益是否角色相关
  • 衍生：得到收益表后可反推轮换周期 T，验证「30s 轴」是否为资源约束的解

实验 D：帧级数据（补全 §5.2、§7）

  • 变奏无敌帧时长（逐帧）
  • 切人冷却时长，及受击打断是否重置 CD（对应 §6 问题 3）
  • 切人输入缓冲窗口帧数

产出物

Excel 验证表，四列格式：理论值 / 实测值 / 绝对误差 / 相对误差。相对误差 < 0.1% 视为假设成立。实测完成后本文升版至 v1.1，并在对应结论处标注「已实证」或「已修正」。
